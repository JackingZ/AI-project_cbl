## 一、角色菜单权限系统（登录按角色过滤菜单/页面）

**需求**：后台可配「每个角色能看哪些菜单」，用户登录后仅见其角色授权的菜单，未授权页面手输地址也拦截。

**实现**
- `src/store/permission.js`（新增）：持有 `menuPerms`；`loadByRole` / `hasPerm(path)` / `setPerms` / `reset`。缓存结构 `{ role, perms }` 存 `localStorage.jht_menu_perms`。
  - 规则：`/dashboard` 恒放行；未加载不拦截（防守卫竞态）；`['*']` 全放行；否则白名单命中。
  - 超级管理员硬编码恒定 `['*']`，不受任何配置影响（`SUPER_ADMIN_ROLE` 常量短路）。
  - 默认拒绝：角色 `menuPerms` 为空 → 仅首页可见。
- `src/api/modules/organizers.js`：角色记录加 `menuPerms` 字段；新增 `MENU_TREE`（模块→叶子页面 path，与路由一致）；`getPersonnelByUsername`；`ROLE_MENU_PERMS` 种子表 + 旧数据迁移（缺 menuPerms 按角色名补默认）。
- `src/api/modules/auth.js`：登录按 username 查人员台账得 `roleName`（admin 固定超管，未登记默认客服专员）。
- `src/store/user.js`：登录 `loadByRole`；`ensurePerms`（缓存角色≠当前角色则重载）；`syncRole`（人员管理改本人角色时即时重载）；登出 `reset`。
- `src/router/index.js`：守卫改 async，`ensurePerms` 后校验 `to.meta.activeMenu || to.path`，无权限回首页提示。
- `src/components/Layout/Sidebar.vue`：`menuList` 按 `hasPerm` 过滤，模块无可见子项则整块隐藏。
- `src/views/organizers/Role.vue`：菜单权限配置 UI（后演进为权限矩阵，见第二节）。
- `src/views/login/Index.vue`：演示账号提示。

**演示账号（任意密码）**：admin 超管(全部) / user05 运营主管 / user02 客服专员 / user03 财务专员 / user04 代理商管理员。

**踩坑**
- 旧缓存 `jht_db_org_role` 无 `menuPerms` + 兜底方向错（缺失回退 `['*']`）→ user02 看到全部菜单。修正为**默认拒绝** + 种子迁移 + 缓存带 role 失效重载。

**产出文档**：`agent/prds/prd-role-permission.md`（PRD + Mermaid 结构图/流程图）。

## 二、机构管理页面与原项目一致性对齐

对照 `workProject2-jht/src/views/organizers-management/` 逐页对齐数据与跳转方式。

**权限设置重建（替代第一节菜单树方案）**

- 页面勾选→ `menuPerms`（登录过滤逻辑不变），按钮勾选→ `perms`；超管免配置。

**数据完整对齐**

**人员跨公司数据 + 缓存版本机制**
- 问题：人员全部 `custName:'SYSTEM总部'`，超管看不到其他公司人员。
- 修复：人员扩到 30 条 + `custType`，跨SYSTEM/客户/代理商/供应商分布；页面加「公司类型/所属公司」筛选与列；`getPersonnelList` 支持过滤，新增 `getCustNameOptions`。
- `persist.js` `createResource` 新增 `version` 参数：种子升级旧缓存自动作废重建；personnel/customer/agent/supplier 四资源版本升至 `2`。

**刻意保留**
- 人员**单角色**（改多角色会破坏已验证的登录/菜单过滤），仅补 所属岗位/设置密码/强制改密。
- 权限矩阵不含「权限点 CRUD/请求接口/请求方式」（后端权限节点管理，纯前端 mock 无意义）。

**记录**：已补记 `agent/migration.md` 第十节。

## 七、机构管理按钮权限接入（perms 生效）

**需求**：补充机构管理页面的按钮权限（此前 10.2 的按钮 `perms` 仅可勾选保存、未拦截）。经确认：未授权按钮**置灰禁用**（非隐藏）；**超管全放行，其余严格按 perms**（不改种子）。

**实现**
- `store/permission.js`：`state` 增 `btnPerms`；`setPerms/loadByRole` 同步角色 `perms`（超管 `['*']`）；`jht_menu_perms` 持久化增 `btns`；新增 `hasBtn(id)`（未加载/`['*']` 放行，否则命中 `${path}:${action}`）。
- `utils/hooks.js`：新增 `usePagePerms(basePath?)` → `can(action)`，按当前路由 path 拼 id 调 `hasBtn`。
- 6 页（Role/Personnel/Department/Customer/Agent/Supplier）按钮加 `:disabled="!can('xxx')"`。映射：新增·批量导入→add，查看·更多→view，编辑·状态·修改归属·审核·重置密码→edit，删除→del。
- `Role.vue` 保存本人角色时 `setPerms(menuPerms, undefined, perms)`，按钮权限即时生效。
- 校验 MENU_TREE 页面 id 与路由 path 完全一致（`/organizers/xxx`），`can()` 解析正确。
- 其余业务模块暂未接入，后续同法用 `usePagePerms`。
