# 订单签收 一致性审计

源: `agent/workProject2-jht/src/views/orderlist-management/order-sign/index.vue` (+ `searchMore.vue`)
目标: `src/views/orderlist/OrderSign.vue`
路由: `/orderlist/order-sign` (name `OlSign`)

> 结构上订单签收 ≈ 全程订单的裁剪版（同一 detail.vue、同一筛选/表格骨架），差异集中在操作列(签收)与更多筛选。

## 筛选项比对

主搜索区（源）：一级代理商(custType0)、公司类型、所属公司、审核状态、业务类型、目的国家、FBA仓库、服务、下单时间、关键字(前置 原单号/客户名称/柜号)、查询。
更多筛选抽屉 searchMore（源）：入库状态、计量状态、验货状态、报关状态、支持锁舱(type1/2)、是否发货、派送方式(卡派/自提/整柜直送——注意无"快递")、报关方式、关税方式、是否冻结。

目标筛选：订单状态、审核状态、业务类型、关键字(前置 原单号/客户名称/柜号 code/customerName/containerNo)、更多展开：一级代理商(TOP_AGENTS)、订单类型、公司类型、所属公司、目的国家、FBA仓库、服务、下单时间。

| 项 | 源 | 目标 | 结论 |
|---|---|---|---|
| 一级代理商 | select 远程(custType0) | 更多内 select TOP_AGENTS 占位 | 目标保留(占位)，良好 |
| 公司类型/所属公司 | select | 更多内占位 | 一致 |
| 审核状态 | select 4值 | select AUDIT_STATUS | 一致 |
| 业务类型 | select 空运/海运/铁路/卡航 | select BUSINESS_TYPES | **差异**：同全程订单，业务类型枚举语义错，应为 ['空运','海运','铁路','卡航'] |
| 目的国家/FBA仓库/服务 | select 远程 | 更多内占位 | 一致 |
| 下单时间 | daterange | 更多内 daterange | 一致 |
| 关键字前置 | 原单号/客户名称/柜号 | 同(code/customerName/containerNo) | 一致 |
| 订单类型 | (源未在主区，仅注释) | 目标更多内新增 ORDER_TYPES | 目标有源无。无害 |
| 订单状态 | 源主区已注释 lineStatusList | 目标新增 ORDER_STATUS | 目标有源无。无害 |
| **更多抽屉状态项** | 入库/计量/验货/报关状态、锁舱、是否发货、派送方式、报关方式、关税方式、是否冻结 | 目标更多区未含任一 | **缺漏**：searchMore 的状态类筛选项全部缺失（同全程订单问题）|

## 表格列比对

源列：订单信息、客户名称(fixed)、下单客户、下单时间、下单仓库、货物所在仓、报关方式、提货方式、派送方式、件数、金额、是否发货、审核状态(带红点tooltip拒绝原因)、入库状态、出库状态、计量状态、验货状态、报关状态、预估运费、截止付款时间、逾期天数。

目标列：订单信息、客户名称、下单客户、下单时间、下单仓库、货物所在仓、报关方式、提货方式、派送方式、件数、金额、是否发货、审核状态、入库状态、出库状态、计量状态、验货状态、报关状态、预估运费、截止付款时间、逾期天数。

| 列 | 结论 |
|---|---|
| 全部列 | **完整覆盖**，与源一一对应，顺序一致 |
| 审核状态红点(拒绝原因 tooltip) | 目标用 auditStatusTag tag 呈现，无红点 tooltip。小简化，可接受 |

结论：表格列**无缺漏**，对齐优秀（注意：签收页比全程订单少了计量审核/快递单号/账单列，目标也正确地少了这些，符合源）。

## 操作按钮比对

源操作列：
- 查看 `v-permission="['signOrderView']"`
- 签收/已签收 `v-permission="['signOrder']"`，文案随 `statusFiles[9020]` 切换"已签收"/"签收"，点击开签收弹窗(上传签收单+签收时间)

目标操作列：
- 查看 openDetail 弹窗
- 签收(signStatus==='待签收' 时 confirmThen 调 signOrder) / 已签收(disabled)

| 按钮 | 源权限键 | 目标 | 结论 |
|---|---|---|---|
| 查看 | signOrderView | openDetail 弹窗 | 一致 |
| 签收 | signOrder | confirmThen 确认框调 signOrder API | **差异**：源签收是弹窗表单（签收时间 datetime + 上传签收单文件，必填校验），目标简化为纯确认框。签收单上传/签收时间字段缺失。属较大简化——若保真应做签收弹窗(签收时间+签收单上传) |
| 已签收态 | - | disabled 按钮 | 一致（文案切换还原）|

## 详情弹窗字段

同全程订单，用通用 OrderDetailDialog。签收特有字段(签收时间/签收单)未在详情呈现，属简化。

## 权限键接入缺口（重点）

目标未接入 usePagePerms。建议 basePath `/orderlist/order-sign`：
- `can('view')` → 查看（源 signOrderView）
- `can('sign')` → 签收（源 signOrder）

建议 can 动作集：**view, sign**

## 评分：小差异

优点：表格列全覆盖、签收/已签收态还原。
问题：①业务类型枚举语义错；②更多筛选状态项全缺；③签收改纯确认框(丢失签收时间+签收单上传弹窗)；④权限键 0 接入。
