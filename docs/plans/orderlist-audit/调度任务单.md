# 调度任务单 一致性审计

- 源：`agent/workProject2-jht/src/views/orderlist-management/car-order/allocationCat.vue`
- 目标：`src/views/orderlist/AllocationCat.vue`
- 背景：新增可见页（源里 hidden 被注释=可见）。数据用派生 getScheduleTasks。

## 一、重要发现：源与目标是两种不同页面语义

源 allocationCat 实为**卡派订单的"调度任务"视图**（`isTask:'0'` 的 getCarOrderList），列/筛选与卡派订单几乎一致，只是操作换成"分配车辆/完成"，还带多选 checkbox。它**不是**独立的"任务单号/车队/司机/车牌"资源列表。

目标 AllocationCat 是一个**全新设计的调度任务单资源**（taskNo/fleet/driverName/cardId/status/orderCount/createTime + 新建/查看）。

→ migration/orderlist-align 已明确此为"新增页 + 新派生 getScheduleTasks"的**刻意重设计**，非保真。以下按"是否达成对齐文档目标"审计，并列出与源真实结构的差异供参考。

## 二、筛选项

源(allocationCat)：订单状态(3值:待分配/司机取消订单/完成调度)、目的地(focus 拉取)、下单时间(默认近30天)、原单号 + 查询(`allocationQuery`)。
目标：任务状态(SCHEDULE_STATUS)、关键字(任务单号) + 新建调度任务单。

结论：筛选项完全不同（因页面重设计）。**目标缺（相对源）**：目的地、下单时间范围、原单号→改为任务单号关键字。属刻意重设计，标注即可。

## 三、表格列

源列：selection(多选) · 原单号 number · 订单状态(3值) · 下单时间 · 业务类型 goodsName · 下单客户 customerName · 客户名称(custType=0) · 提货方式 delivery(4值) · 提货日期 planTime · 目的地 · 送货日期 pickTime · 备注 remake。
目标列：任务单号 taskNo · 车队 fleet · 司机 driverName · 车牌 cardId · 任务状态 status · 订单数 orderCount · 创建时间 createTime。

结论：列语义完全不同（订单明细列 vs 任务单汇总列）。目标符合对齐文档定义的列集合（任务单号/车队/司机/车牌/状态/订单数/创建时间），达成文档目标。**与源真实列不一致**属重设计。

## 四、操作按钮

| 源按钮 | 权限键/条件 | 目标 | 结论 |
|---|---|---|---|
| 新建调度任务单 | 注释态 `allocationAdd` | 有"新建调度任务单"(openCreate 弹窗建单) | 目标补齐，OK（源为注释态） |
| 查询 | `allocationQuery` | search（SearchBar 内置） | 无权限键 |
| 查看 | `getTask` | 有"查看"(Modal 详情) | OK |
| 分配车辆 | `distributionTask`，custId=0 | 无 | 源有目标无（因重设计为任务单，分配车辆并入卡派页）。标注 |
| 完成 | `distributionComplete`，custId=0 | 无 | 源有目标无。标注 |
| 第三方车辆 | 注释态 `thirdparty` | 无 | 注释态，忽略 |

## 五、详情弹窗字段

目标 Modal：任务单号/车队/司机/车牌/任务状态/订单数/创建时间（对齐新资源列）。
源"查看"→ 卡派 detail.vue（发货人/收货人/货物信息全套）。
结论：不可比（重设计）。目标详情自洽。

作为"对齐文档定义的新增任务单页"实现完整、自洽。但相对源真实页面（卡派调度视图）为整体重设计：筛选/列/操作三者语义均不同，且丢失了"分配车辆/完成"两个源操作。0 权限键接入。若目标是保真源页则评分低；按 migration 重设计意图则达标。建议在页面或文档中显式标注"本页为重设计，非源 allocationCat 保真"。
