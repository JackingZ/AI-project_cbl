# 代客下单 一致性审计

源: `agent/workProject2-jht/src/views/orderlist-management/salesman-order/index.vue` (+ 录单 `salesman.vue`)
目标: `src/views/orderlist/SalesmanOrder.vue` (+ 录单 `SalesmanAdd.vue`)
路由: `/orderlist/salesman-order` (name `OlSalesman`)，录单 `/orderlist/salesman-add` (name `OlSalesmanAdd`)

> 录单页 salesman.vue 是走路由跳转的场景（约定：录单/调度走路由），目标 goEntry 用 `router.push({name:'OlSalesmanAdd'})`，符合约定。

## 筛选项比对

源：所属客户(select 远程 comId)、订单状态(lineStatusList)、录单状态(未录单/已录单 0/1)、审核状态(4值)、业务类型(空运/海运/铁路/快递/卡航 id0-4)、目的国家、FBA仓库、服务(依赖 type+country)、下单时间、关键字(前置仅"原单号")、查询。

目标：所属客户(input)、订单状态(ORDER_STATUS)、录单状态(ENTRY_STATUS 已录单/未录单)、审核状态(AUDIT_STATUS)、关键字(前置 原单号 code)、更多展开：业务类型(BUSINESS_TYPES)、目的国家、FBA仓库、服务、下单时间。

| 项 | 源 | 目标 | 结论 |
|---|---|---|---|
| 所属客户 | select 远程 | input 输入框 | 一致（占位降级为 input）|
| 订单状态 | select LINE 状态 | select ORDER_STATUS 占位 | 一致（占位）|
| 录单状态 | 未录单/已录单 | ENTRY_STATUS(已录单/未录单) | 一致 |
| 审核状态 | 4值 | AUDIT_STATUS | 一致 |
| 业务类型 | 空运/海运/铁路/快递/卡航 | 更多内 BUSINESS_TYPES(快递/订舱/卡派/拖车/报关) | **差异**：源含 空运/海运/铁路/快递/卡航（注意此页比全程订单多"快递"）；目标套通用枚举，语义错。建议改 ['空运','海运','铁路','快递','卡航'] |
| 目的国家/FBA仓库/服务 | select 远程 | 更多内占位 | 一致 |
| 下单时间 | daterange | 更多内 daterange | 一致 |
| 关键字前置 | 仅"原单号"(业务编码/备注已注释) | 前置仅 原单号 | 一致 |

## 表格列比对

源列：订单信息(服务+原单号)、录单状态、报关方式、提货方式、客户名称(custType0)、件数、金额、审核状态(红点)、订单状态、入库状态、出库状态、计量状态、验货状态、报关状态、快递单号(popover)、账单(--)、付款(--)。

目标列：订单信息、录单状态、报关方式、提货方式、客户名称、件数、金额、审核状态、订单状态、入库状态、出库状态、计量状态、验货状态、报关状态、快递单号、账单。

| 列 | 源 | 目标 | 结论 |
|---|---|---|---|
| 订单信息~报关状态 | 全部 | 全部覆盖 | 一致 |
| 快递单号 | popover 展开单号 | 列存在 | 一致（简化为文本）|
| 账单 | 占位"--" | billStatus 列(开 BillDialog) | 目标增强，无害 |
| 付款 | 占位"--" | **无** | 目标缺"付款"列。源为纯占位"--"无实际数据，缺失影响极小，可标注不计 |

结论：表格列基本无缺漏（仅少一个纯占位"付款"列）。

## 操作按钮比对

源：查看(无权限键，viewData 页面切换) / 录单(`salesmanStatus==='0'` 且 `v-permission="['salesmanOrderInput']"`，页面切换到录单页)。

目标：查看(openDetail 弹窗) / 录单(goEntry 路由跳转 OlSalesmanAdd)。

| 按钮 | 源权限键 | 目标 | 结论 |
|---|---|---|---|
| 查看 | 无 | openDetail 弹窗 | 一致 |
| 录单 | salesmanOrderInput | router.push OlSalesmanAdd | 一致（录单走路由符合约定）；但源有 `salesmanStatus==='0'`(未录单才显示)条件，目标无条件恒显示。**小差异**：建议录单按钮加"已录单则不显示/禁用"逻辑 |

顶部：源无"导出/已出"操作；目标 actions 放了 `demoAction('已出')` 按钮——**目标有源无**，且"已出"语义不明（像是从快递单号列误挪来的）。建议移除该顶部按钮。

## 录单页 SalesmanAdd.vue 比对

源 salesman.vue 未逐字段核（深层录单表单）。目标 SalesmanAdd：订单信息(业务类型/客户名称/下单客户/目的国/备注) + 商品明细表格(名称/HS编码/数量/单价/箱数/单箱重量) + 合计 + 提交。为合理的录单表单实现，功能完整。业务类型下拉同样用了 BUSINESS_TYPES(可对齐运输方式，一致性小问题)。

## 详情弹窗字段

通用 OrderDetailDialog，覆盖基础字段。录单状态字段未在详情呈现，简化可接受。

## 权限键接入缺口（重点）

目标未接入 usePagePerms。建议 basePath `/orderlist/salesman-order`：
- `can('view')` → 查看
- `can('entry')` → 录单（源 salesmanOrderInput）

建议 can 动作集：**view, entry**

## 评分：小差异

优点：列覆盖、录单走路由符合约定、录单页表单完整。
问题：①业务类型枚举语义错(应含快递的5值)；②顶部多了无意义"已出"demo 按钮；③录单按钮缺"未录单才显示"条件；④权限键 0 接入。
