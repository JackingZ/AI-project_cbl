# 状态设置 StatusConfig 一致性核对

- 源：`agent/workProject2-jht/src/views/system-management/status-config/index.vue`（Vue2）
- 目标：`src/views/system/StatusConfig.vue`（Vue3 通用 CRUD 骨架）
- 源权限键：**无 v-permission**（路由 meta 无 roles，isJHT: true）——页面级 JHT 专属，按钮无独立权限键
- 一致性评分：**严重错配**（源是「状态-角色权限矩阵」维护，目标是普通状态字典 CRUD）

## 结论速览
源是给**每个业务状态配置「哪些角色可查看 / 可下载文件」**的权限矩阵页：按服务大类筛选、排序，列表展示状态及其可见/可下载角色，两个弹窗分别做「权限设置（5 角色 × 仅查看/可下载 复选）」和「修改描述（排序值 + 描述）」。目标做成了「状态名称/编码/场景/状态开关」的字典 CRUD，**核心的角色权限矩阵完全丢失**。

## 子组件
无。源用全局服务大类接口 getServiceTypeList。

## 建议 can 动作
- can editPerm（权限设置，源无独立键，属页面级 JHT 专属）
- can editDesc（修改描述/排序）
- 无 can add / can del / can toggle（源均无，目标属虚构）

## 需补要点（真实业务缺漏）
整页重写为「状态-角色权限矩阵」：
1. 筛选：排序(升/降) + 服务大类 select + 查询。
2. 列：排序值 / 状态名称 / 服务大类(statusType 映射) / 描述 / 是否有文件 / 权限(仅查看+可下载 角色名)。
3. 弹窗A「权限设置」：5 角色 × (仅查看 / 可下载 有文件时) 复选矩阵。
4. 弹窗B「修改描述」：排序值(必填) + 描述。
5. 行操作改为「权限设置 / 修改描述」两按钮。
6. 移除虚构的 新增/删除/状态开关/编码/场景/创建时间。
