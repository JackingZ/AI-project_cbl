# 通知配置一致性核对（源 workProject2-jht Vue2 → 目标 Vue3）

- 源：`agent/workProject2-jht/src/views/system-management/notice-config/index.vue`（树形通知开关）+ `noticePerson.vue`（通知接收人子弹窗）
- 目标：`src/views/system/NoticeConfig.vue`（单文件通用 CRUD，mock=`noticeCfgApi`，字段虚构）

> **核心结论：源是"通知类型树 + 多通知方式勾选(站内信/手机/邮箱/微信/app) + 通知接收人配置"的树形配置页；目标虚构成"通知名称 + 渠道 + 触发事件"的列表 CRUD，页面形态根本错配。**

---

## 1. 筛选项
- 源：**无筛选**（树形全量展示）。
- 目标：通知名称 name、渠道 channel(站内/短信/邮件)、状态 status。

| 判定 | 项 | 说明 |
|---|---|---|
| 目标有源无=错配 | 全部筛选项 | 源为树形无搜索区 |

## 2. 主体形态（表格 vs 树）
- 源：`el-tree`(show-checkbox, node-key=unqId, 默认展开)。表头三列：**通知类型 / 通知方式 / 通知人**。
  - 二级节点(node.level===2)每行：5 个复选框(**站内信 mail / 手机 phone / 邮箱 notification / 微信 wechat / app**，权限 `updateNotificationMethodConfig`) + "修改通知接收人"按钮(权限 `noticeUpdataPerson`)。
  - 树勾选(onCheck)= 开关该通知类型 status(saveNotice)；方式勾选(checkChange)= updateNotice。
- 目标：`ProTable` 列：通知名称 name、渠道 channel、触发事件 event、状态 status(switch)、创建时间。

| 判定 | 项 |
|---|---|
| 源有目标无=需补 | **树形结构**(通知类型父/子层级) |
| 源有目标无=需补 | **5 种通知方式勾选**(站内信/手机/邮箱/微信/app) |
| 源有目标无=需补 | **通知类型级 status 开关**(树 checkbox) |
| 源有目标无=需补 | **"修改通知接收人"入口** |
| 目标有源无=错配 | 渠道 channel、触发事件 event 列 | 源无此字段，虚构 |
| 字段差异=错配 | 页面形态：树 vs 列表 |

## 3. 表单字段
- 源无"新增/编辑"CRUD 表单；配置直接在树上勾选保存。
- 目标 Modal：通知名称 name、渠道 channel、触发事件 event、状态 status。

| 判定 | 项 |
|---|---|
| 目标有源无=错配 | 整个新增/编辑弹窗（源无此交互） |

## 4. 子弹窗 noticePerson（通知接收人）
- 源 `noticePerson.vue`：弹窗"添加地址"，行内编辑表格：**服务类型 service**(远程下拉)、**业务类型 subtypeIds**(多选，随服务联动)、**接收者 userIds**(多选用户)、操作(编辑/保存/删除/取消)。含重复校验(相同服务+业务+接收者去重)、行内新增/保存/删除(savePerson/editPerson/deletePerson)。
- 目标：**完全缺失**。

| 判定 | 项 |
|---|---|
| 源有目标无=需补 | **整个通知接收人配置弹窗**(服务类型/业务类型/接收者行内编辑 + CRUD + 重复校验) |

## 5. 操作按钮 + v-permission
源逐字权限键：通知方式勾选 `updateNotificationMethodConfig`、修改通知接收人 `noticeUpdataPerson`(均 `$checkPermission` 控 disabled)。
目标：0 权限；通用"新增/编辑/删除"。

| 判定 | 项 |
|---|---|
| 需补(权限) | 2 个权限键未接入 |
| 源有目标无 | 修改通知接收人 |
| 目标有源无 | 新增/编辑/删除 CRUD 按钮(源无) |

## 一致性评分：通知配置 **12 / 100**
最严重错配页。源为"通知类型树 + 5 种通知方式勾选 + 通知接收人(服务/业务/接收者)配置弹窗"的树形配置页，目标虚构成"通知名称/渠道/触发事件"通用列表 CRUD，页面形态、通知方式、接收人子弹窗全部缺失。需整页按源树形业务重写。

## 建议 can 动作
`can('editMethod')` 修改通知方式（源 updateNotificationMethodConfig）、`can('editPerson')` 修改通知接收人（源 noticeUpdataPerson）。无标准增删改。
