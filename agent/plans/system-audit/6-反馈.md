# 反馈 Feedback 一致性核对

- 源：`agent/workProject2-jht/src/views/system-management/feedback/index.vue`（Vue2）
- 目标：`src/views/system/Feedback.vue`（Vue3 通用 CRUD 骨架）
- 源权限键：**无 v-permission**（路由无 roles，isJHT: true）——页面级 JHT 专属
- 一致性评分：**较大差异**（列表形态相近，但源是「只读+处理」流程，目标错做成可增删改的 CRUD）

## 结论速览
源是用户反馈的**受理台**：按来源/状态/时间筛选，列表只读展示，点「详情」看内容+页面截图并做「忽略/已处理」流转，或「删除」。**不能新增、不能编辑反馈内容**（反馈由前端用户提交）。目标却给了「新增 + 编辑」弹窗，且用可编辑的「反馈标题/客户/类型/处理状态」表单——语义错配。

## 筛选项
| 项 | 源 | 目标 | 结论 |
|----|----|----|----|
| 反馈来源 type select | 有（着陆页/后台管理系统，值 0/1）| 有「类型」select（建议/投诉/咨询）| 语义+选项差异：源=来源，目标=反馈分类 |
| 状态 status select | 有（未处理0/已处理1/忽略2）| 有「处理状态」（待处理/已处理，仅2项）| 差异：源3态含「忽略」|
| 创建时间 daterange | 有（startTime/endTime）| 无 | 【源有目标无=需补】|
| 反馈标题 name 输入 | 无 | 有 | 【目标虚构】源无标题搜索 |

| 反馈账号 | `name` | `name`（label 反馈标题）| 语义差异：源=反馈账号 |

| 目标字段 | 结论 |
|----|----|
| 反馈标题 name / 客户 customer / 类型 type / 处理状态 handle | 【全部目标虚构】源不允许人工新建/改写反馈 |

## 操作按钮
| 按钮 | 源文案/权限/交互 | 目标 | 结论 |
|----|----|----|----|
| 查询 | `查询` queryAll(1) | 无（骨架自动）| 交互差异 |
| 详情 | `详情` 弹窗（getFeedBackById，展示截图）| 无（改为「编辑」弹窗）| 【需补】can **view/detail**（跳弹窗→保真为详情非编辑）|
| 删除 | `删除` 二次确认 delFeedback | `删除` 通用确认 | can **del**（源无权限键）|
| 忽略 | 详情弹窗内 `忽略`（handleFeedback('2')，仅 status=0 显示）| 无 | 【需补】can **handle/ignore**|
| 已处理 | 详情弹窗内 `已处理`（handleFeedback('1')，仅 status=0 显示）| 无 | 【需补】can **handle/resolve**|
| 大图预览 | 详情内点击截图 → 大图弹窗 | 无 | 【需补】|
| 新增 | 无 | `新增` 弹窗 | 【目标多余/虚构】|
| 编辑 | 无 | `编辑` 弹窗 | 【目标多余/虚构】源反馈不可编辑 |

## 子组件
无（源两个 el-dialog：详情 + 截图大图）。目标用通用 Modal。

## 建议 can 动作
- can view（详情，含截图预览）
- can handle（处理：忽略/已处理，仅未处理态可用）
- can del（删除）
- 无 can add / can edit（源不允许人工新建或改写反馈内容，目标属虚构）
- 源无按钮级权限键（页面级 isJHT），can 按页面统一

## 需补要点（真实业务缺漏）
1. 「详情」弹窗替代目标的「编辑」弹窗：只读展示 反馈账号/内容/状态/页面截图（缩略图+大图预览）。
2. 详情内「忽略 / 已处理」两处理动作（仅 status=未处理 显示）。
3. 列补：所属公司 companyName、反馈内容 submitContent；来源(着陆页/后台) 与 状态(未处理/已处理/忽略) 语义与选项对齐。
4. 筛选补：来源、状态(3态)、创建时间 daterange。
5. 移除虚构的 新增/编辑反馈表单、反馈标题搜索、customer 字段。
