**表格列、筛选项、操作按钮**，不得多或少。已定：详情/账单/进度等子页**沿用当前弹窗**，

## 一、菜单结构对齐（router/index.js）
参考顺序：仓库订单 → 全程订单 → 订单签收 → 代客下单 → 报关订单 → 卡派订单 →
**调度任务单** → 快递订单 → 订舱订单 → 拖车订单。
- 调整 orderlistModule children 顺序与参考一致。
- 新增可见页 **调度任务单**（allocationCat，参考里 hidden 被注释=可见）。
- `order-tracking`(订单状态追踪) 参考为 hidden 且在 orderlist 之外 → 不加入菜单。
- `salesman-add`(录单) 保持 hidden。
- `commodity-audit` 参考在 orderlist 内被整段注释 → **不作为菜单页**；它是全程订单行内「订单审核」入口。

## 二、数据模型补齐（api/modules/orderlist.js）
为满足各页新列，给统一订单集补齐字段（中文串/数值），并加派生查询：
- 全程/签收/代客共用：`orderWarehouse`(下单仓库) `goodsWarehouse`(货物所在仓)
  `declareMethod`(报关方式) `pickMethod`(提货方式) `deliverMethod`(派送方式)
  `ifShip`(是否发货) `inStatus`(入库状态) `outStatus`(出库状态)
  `measureStatus`(计量状态) `measureAudit`(计量审核) `inspectStatus`(验货状态)
  `estimateFee`(预估运费) `payDeadline`(截止付款时间) `overdueDays`(逾期天数)
  `billStatus`(账单)。
- 报关：`orderType`(订单类型) `declareType`(报关类型) `fileStatus`(文件状态) `countryName`(服务国家)。
- 卡派：`serviceName`(服务) `serviceProvider`(服务提供商) `sellerName`(下单客户)。
- 拖车：`serviceProvider` `warehouseTime` `pickTime`(取货时间)。
- 快递：`packageType`(包裹类型固定"箱") — 已有 consignee/zip/expressCompany。
- 订舱：已有 soCode/billNo/portFrom/portTo。
- 新增派生：`getScheduleTasks`(调度任务单) + 任务字段（任务单号/车队/司机/状态）。
- 保留现有枚举与 tag 函数；新增少量枚举（报关方式/提货方式等中文选项）。
